## ✅ Why It Works Now

### Google OAuth Fixed

**The Problem:**
```python
# ❌ We managed our own PKCE
code_verifier = generate()
# Error: "code challenge does not match"
```

**The Solution:**
```python
# ✅ Let Supabase handle PKCE
supabase.auth.sign_in_with_oauth({...})
# Supabase manages PKCE internally
```

**Why It Works:**
- Supabase generates PKCE code_verifier + code_challenge
- Supabase stores verifier in its storage
- On callback, Supabase retrieves its verifier
- Everything matches, auth succeeds!

**Lesson:** Don't fight the framework.

## ❌ Why It Failed Initially

### Attempt 1: Custom State
```python
state = generate_random()
oauth_url = f"...&state={state}"
# Error: bad_oauth_state
# Why: Supabase manages its own state
```

### Attempt 2: Manual PKCE
```python
our_verifier = generate()
exchange(code, our_verifier)
# Error: verifier mismatch
# Why: Supabase has different verifier
```

### Attempt 3: Wrong Format
```python
exchange(code)  # String
# Error: str has no attribute 'get'
# Why: Needs dict format
```

**Root Cause:** We interfered with Supabase's internal PKCE management.

## 🔄 How It Works

### 1. Signup Flow
```
User → POST /signup → AuthService → Supabase
→ Email sent → User confirms → Account active
```

### 2. Login Flow
```
User → POST /signin → Verify password
→ Return JWT tokens → Store in frontend
```

### 3. Google OAuth Flow
```
User → GET /google → Supabase generates OAuth URL
→ Redirect to Google → User approves
→ Google redirects with code
→ GET /callback → Exchange code for tokens
→ Return JWT + profile
```

### 4. Token Refresh
```
Access expires → POST /refresh with refresh_token
→ Get new access token → Continue
```

### 5. Profile Access
```
GET /profile/me → Check if exists
→ If not, create from auth data
→ Return profile
```

## 🔐 Security

- **Passwords:** Bcrypt hashed, never stored plaintext
- **JWT:** HS256 signed, 1-hour expiry
- **PKCE:** Prevents code interception
- **RLS:** Row-level security in database
- **HTTPS:** Required in production

## 💾 Avatar Storage

**Question:** Where are avatars stored?

**Answer:**
- **Database:** Stores URL as text (`"https://i.imgur.com/abc.jpg"`)
- **Actual image:** On Imgur (user uploads)
- **NOT in database:** Image bytes

**Benefits:**
- No storage costs
- No file uploads
- Simple implementation


```bash
curl http://localhost:8000/api/profile/me \
  -H "Authorization: Bearer <token>"
```

### Update Profile
```bash
curl -X PATCH http://localhost:8000/api/profile/me \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"full_name":"John Doe","avatar_url":"https://i.imgur.com/abc.jpg"}'
```

## 🐛 Common Issues

### 1. Profile Not Found
**Solution:** Profiles auto-create now. Just call GET /profile/me

### 2. OAuth Fails
**Check:**
- Callback URL matches everywhere
- SUPABASE_URL is correct
- Google OAuth credentials are set

### 3. Token Expired
**Solution:** Use refresh token endpoint

### 4. CORS Errors
**Solution:** Add your frontend URL to CORS origins

## 📊 Database Schema

```sql
CREATE TABLE profiles (
  id UUID PRIMARY KEY REFERENCES auth.users(id),
  email TEXT NOT NULL,
  full_name TEXT,
  avatar_url TEXT,
  phone TEXT,
  company TEXT,
  role TEXT DEFAULT 'user',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 🎓 Key Learnings

1. **Let frameworks do their job** - Don't implement what's already built-in
2. **Modular > Monolithic** - Separate concerns for maintainability
3. **Services layer** - Business logic separate from routes
4. **Auto-recovery** - Create profiles on-the-fly if missing
5. **Simple storage** - URLs > File uploads for avatars
