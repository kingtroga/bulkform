# BulkForm PDF Processing API - Complete Documentation

## 🎯 Project Overview

**BulkForm** is a production-ready REST API for programmatically filling PDF forms with text and images. Built for immigration lawyers and professionals who need to fill multiple forms efficiently.

### Key Features
- ✅ **Grid-based coordinate system** (150x150) for precise placement
- ✅ **Authentication** via Supabase (JWT + Google OAuth)
- ✅ **Database-backed sessions** (survives server restarts)
- ✅ **Cloud storage** (Supabase Storage for permanence)
- ✅ **End-to-end encryption** (protect your API from competitors)
- ✅ **Custom fonts support** (upload your own .ttf fonts)
- ✅ **Batch operations** (fill multiple pages at once)
- ✅ **Session restoration** (edit completed PDFs)
- ✅ **Preview system** (see before generating)
- ✅ **Private storage** with signed URLs (1-hour expiry)

---

## 🏗️ Architecture

### Tech Stack
- **Backend**: FastAPI (Python)
- **Database**: Supabase PostgreSQL
- **Storage**: Supabase Storage (private bucket)
- **Auth**: Supabase Auth (JWT + OAuth)
- **PDF Processing**: Pillow, pdf2image, img2pdf
- **Encryption**: Fernet (symmetric encryption)

### Folder Structure
```
project/
├── app.py                      # FastAPI application
├── routes/
│   ├── pdf_routes.py           # PDF processing endpoints
│   └── google_auth.py          # OAuth routes
├── services/

├── models/

```

### Data Flow
```
1. User uploads PDF
   ↓
2. Backend converts to images (300 DPI)
   ↓
3. Original PDF saved to Supabase Storage
   ↓
4. Session created in database
   ↓
5. Grid coordinates returned to frontend
   ↓
6. User fills text/adds signatures (multiple requests)
   ↓
7. Final PDF generated
   ↓
8. Uploaded to Supabase Storage (signed URL)
   ↓
9. Local temp files cleaned up
   ↓
10. Session marked as "completed"
```

## 🗄️ Database Schema

### Table: `pdf_sessions`
```sql
CREATE TABLE pdf_sessions (
    id BIGSERIAL PRIMARY KEY,
    session_id UUID UNIQUE NOT NULL,
    user_id UUID NOT NULL REFERENCES auth.users(id),
    filename TEXT NOT NULL,
    num_pages INT NOT NULL,
    status TEXT DEFAULT 'processing',  -- processing, completed, failed
    storage_path TEXT,
    download_count INT DEFAULT 0,
    last_downloaded_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Row Level Security (RLS)
ALTER TABLE pdf_sessions ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can only access their own sessions"
ON pdf_sessions
FOR ALL
USING (auth.uid() = user_id);
```

### Supabase Storage Structure
```
Bucket: pdfs (PRIVATE)
├── {user_id}/
│   └── {session_id}/
│       ├── original.pdf        # Original uploaded PDF
│       └── output_complete.pdf # Final filled PDF
```

## 🔐 Encryption System

### Purpose
Protect your API from competitors by encrypting:
1. Grid coordinates (sent TO frontend)
2. Fill data (sent FROM frontend)

### Setup

**1. Generate encryption key:**
```bash
# Run this once
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

**2. Add to `.env`:**
```bash
GRID_ENCRYPTION_KEY=your_generated_key_here
```

**3. Share key with frontend:**
```javascript
// Frontend .env
REACT_APP_GRID_ENCRYPTION_KEY=your_generated_key_here
```

### Frontend Encryption Example

**JavaScript (using CryptoJS):**
```javascript
import CryptoJS from 'crypto-js';

const ENCRYPTION_KEY = process.env.REACT_APP_GRID_ENCRYPTION_KEY;

// Encrypt fill data before sending
export function encryptFillData(data) {
    const jsonString = JSON.stringify(data);
    const encrypted = CryptoJS.AES.encrypt(jsonString, ENCRYPTION_KEY).toString();
    return btoa(encrypted); // Base64 encode
}

// Decrypt grid data from backend
export function decryptGridData(encryptedData) {
    const decoded = atob(encryptedData); // Base64 decode
    const decrypted = CryptoJS.AES.decrypt(decoded, ENCRYPTION_KEY);
    return JSON.parse(decrypted.toString(CryptoJS.enc.Utf8));
}

// Usage
const fillData = {
    page_number: 1,
    text_data: [
        {x: 25, y: 30, text: "John Doe", size: 24, font: "arial"}
    ]
};

const encrypted = encryptFillData(fillData);

await fetch('/api/pdf/fill-text-encrypted', {
    method: 'POST',
    headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({
        session_id: sessionId,
        encrypted_data: encrypted
    })
});
```

## 🎨 Grid Coordinate System

### How It Works
- **Grid Size**: 150 × 150 cells
- **DPI**: 300
- **Coordinate Origin**: Top-left (0, 0)

### Example Calculation
```
PDF page: 8.5" × 11" at 300 DPI
→ Image size: 2550px × 3300px

Cell width: 2550 / 150 = 17px
Cell height: 3300 / 150 = 22px

Grid coordinate (25, 30):
→ Pixel X: 25 × 17 = 425px
→ Pixel Y: 30 × 22 = 660px
```

### Text Alignment
- **top**: Text starts below the coordinate
- **center**: Text centered on the coordinate
- **bottom**: Text ends above the coordinate

## 🚨 Error Handling

### Common Errors

**401 Unauthorized**
```json
{"detail": "Invalid authentication token"}
```
→ JWT token expired or invalid

**403 Forbidden**
```json
{"detail": "Session not found or unauthorized"}
```
→ Trying to access someone else's session

**404 Not Found**
```json
{"detail": "Session not found and cannot be restored"}
```
→ Session doesn't exist or original PDF missing

**500 Internal Server Error**
```json
{"detail": "Fill text failed: No such file or directory"}
```
→ Session cleaned up but restoration failed

## 🎓 Best Practices

### For API Users

**1. Always use encrypted endpoints in production:**
```javascript
// ✅ Good
POST /api/pdf/fill-text-encrypted

// ❌ Bad (exposes coordinates)
POST /api/pdf/fill-text
```

**2. Preview before generating:**
```javascript
// Check page looks correct
GET /api/pdf/preview/{session_id}/page/1

// Then generate
POST /api/pdf/generate?session_id={session_id}
```

**3. Use batch endpoints for multi-page forms:**
```javascript
// ✅ Good (1 API call)
POST /api/pdf/fill-text-batch

// ❌ Bad (3 API calls)
POST /api/pdf/fill-text (page 1)
POST /api/pdf/fill-text (page 2)
POST /api/pdf/fill-text (page 3)
```

**4. Store session_id for later editing:**
```javascript
// User can return to edit later
const sessions = await fetch('/api/pdf/history');
```

### For Backend Developers

**1. Always verify session ownership:**
```python
session = session_service.get_session(session_id)
if session["user_id"] != current_user['id']:
    raise HTTPException(status_code=403)
```

**2. Clean up temp files after generation:**
```python
pdf_processor.cleanup_folders(session_id)
```

**3. Use RLS policies:**
```sql
-- Users can only see their own data
CREATE POLICY "isolation" ON pdf_sessions
FOR ALL USING (auth.uid() = user_id);
```

**4. Return signed URLs (not public URLs):**
```python
# ✅ Good (expires in 1 hour)
signed_url = create_signed_url(path, 3600)

# ❌ Bad (permanent public access)
public_url = f"{SUPABASE_URL}/storage/v1/object/public/{path}"
```

## 🐛 Troubleshooting

### Issue: "Font not found"
**Solution:** Add .ttf file to `fonts/` directory. Restart server to auto-scan.

### Issue: "Session not found"
**Solution:** Session was cleaned up. Original PDF must be in Supabase Storage for restoration.

### Issue: "Bucket not found"
**Solution:** Make bucket public in Supabase OR use signed URLs (recommended).

### Issue: "Invalid encrypted data"
**Solution:** Ensure frontend and backend use same `GRID_ENCRYPTION_KEY`.

### Issue: "OAuth redirect fails"
**Solution:** Update callback URL in:
1. `.env` file
2. Supabase Dashboard → Auth → URL Configuration
3. Google Cloud Console → OAuth credentials
